# iron-m Agent 后续改进方案（2026-10-26）

依据：《Agent 最新研究调研》（2026-10-26，五个方向约 50 条文献）和这几天实测暴露的问题（评委 4.9 分而负责人 20 条全打"不好"、旧膝伤与"肌酐待复查"串进无关回答、天气被判超出范围、回答 7–15 秒）。

每一步都写清：**现在什么样 → 改成什么样 → 带来什么效果 → 怎么证明**。动手前照惯例把这一步写进 `spec/spec.md` 和 `spec/testing.md`（从 §45 起编号）。

## 一、可靠的前提（每一步都要守）

1. **先能量化，再动手。** 以负责人的人工判断为最终标准：评委分、点赞只用来挑出要人看的对话，不当效果证明。
2. **一次只改一处，改完过三道回归才合入。** 三道回归是：考题规则检查、红线子集（急症、伤病就医、禁忌、拒答）、路由测评（不调模型那一版）。任何一道变差就不合。较大的改动带开关，能一键退回。
3. **红线内容永不自动修改。** 包括急症与拒答词表、就医规则、禁忌动作，只能人改。
4. **只由一个会话按本方案推进。** 最近两个会话同时改 `plugin.py`、`app.js` 和 spec，靠拆暂存才没冲突。本方案执行期间，另一个会话只做负责人单独指定的事。
5. **跑真实模型前先查 DeepSeek 余额。** 第 0 步实测一次全量考试的花费，之后每一步都写预计花多少。

## 二、步骤与顺序

```
第 0 步 标注与基线 ──► 第 1 步 评委改造 ──┬─► 第 2 步 记忆分领域
                                          ├─► 第 3 步 路由与提速
                                          ├─► 第 5 步 安全与训练方案（可与 2、3 并行）
                                          └─► 第 4 步 Skill 进化管线（必须在第 1 步之后）
                                                 └─► 第 6 步 用真实效果衡量（持续）
```

预计 3–4 周。第 0、1 步是地基：评测不可信，后面每一步都证明不了自己有没有用。

---

### 第 0 步　标注与基线（1–2 天；需要负责人约 40 分钟）

- **现在**：两轮 20 条评分（第一轮全"不好"，§38/§40 后复评 13 好、2 一般）只存在 `/tmp/iron-eval/rate20*.html` 和对话里。`/tmp` 随时会被清掉，也没有结构化的标签可以拿来校准评委。
- **改成**：
  1. 两轮评分落成 `evals/qa/labels/owner.yaml`，每条记：题号、回答原文、好 / 一般 / 不好、原因。
  2. 再扩 40 条，凑到 60 条。来源是真实对话轨迹（`ironm_turn_trace` 里有信号的轮次优先）加考题，用现有的评分页让负责人点"好 / 一般 / 不好"，再写一句原因。
  3. 按 2 : 1 : 1 分成训练、开发、测试三份。开发和测试两份不能放进评委提示词。
  4. 记基线：负责人"好"率、回答字数中位数、延迟中位数和 P90、每轮模型调用次数、运行框架各信号的发生率，以及一次全量考试花多少钱。
- **效果**：之后每一步都能用负责人自己的标准算出"变好还是变差"。
- **证明**：`owner.yaml` 有 60 条带原因的标注，基线数字写进本文件末尾的表。

### 第 1 步　评委改造：从负责人的差评出发（2–3 天，DeepSeek 约每次全量 1 次）

- **现在**：一个评委同时打 5 个维度、每维 1–5 分，平均 4.9。和负责人的一致率接近 0：负责人 20 条全打"不好"，评委几乎全给 5 分。研究里找到的原因是评委偏爱 Markdown、偏爱长答案，1–5 分天然偏高。
- **改成**：
  1. 从 60 条标注的原因里归纳失败类型，例如首句不是答案、答了没问的、原因放前面、强加"如果……就医"、太长、数字没有出处、不专业、漏答了问的某一部分。
  2. **每类一个"是 / 否"检查，规则能判的用规则判**：字数、首句是否含问到的指标或结论、条件式就医句式。其余交给 DeepSeek 判，判之前把回答转成纯文本，提示里放 2–3 条负责人批过的例子，并允许回答"无法判断"。
  3. 用开发集校准每个检查：真有问题时抓到多少（TPR），没问题时正确放行多少（TNR），两个都 ≥ 0.8 才启用。
  4. 考题计分改成"必过项全部满足才算对"，再加扣分项（诊断、答非所问）。数值题由程序从测试数据直接算出答案来比对，不经过评委。
  5. 报告里显示修正后的通过率和区间，不再显示 4.9 分。
- **效果**：改提示词、改流程后，不用负责人每次逐条看，就能知道变好还是变差，也能抓到退步。第 2–5 步都靠它验收。
- **证明**：在**测试集**上，评委"好 / 不好"和负责人一致率 ≥ 80%；各检查的 TPR、TNR 写进报告。
- **依据**：Hamel Husain/Shreya Shankar 的评测指南、Anthropic《Demystifying evals》、Google 布尔评分表（npj Digit Med 2026）、HealthBench、ClinConsensus、Judging the Judges、LLM 评委修正报告。

### 第 2 步　记忆分领域、带适用场景和有效期（2–3 天）

- **现在**：每轮把全部有效记忆都带上，于是问肌酐时扯到膝伤，问血糖时扯到"肌酐待复查"。§37 和 §39 靠规则一个个补漏洞（问数据时不强制装伤痛规程、"尿酸"不算酸痛），但根上没解决。研究测了 18 个模型，跨领域串入的中位失败率是 53%。
- **改成**：
  1. 记忆加"领域"和"适用场景"两项。领域按类别自动对应：伤病归训练康复，饮食限制归饮食，化验相关归化验，作息归作息。场景按规则给默认值，例如膝伤只在下肢训练、跑跳、疼痛相关的问题里用。
  2. 注入时按领域分节，每节写明"只在问题涉及本领域时使用"。和本轮问题领域无关的分节只留一行摘要，不带全文。
  3. "待复查""急性期""这周出差"这类条目加复核日期。过期后转为"待确认"，不再默认带上，并在首页或"我的"页请用户确认还算不算数。
  4. 新增"对系统的要求"一类，例如"回答短一点""先说结论"。这类每轮必带、篇幅很小，不参与按领域筛选。
  5. 提取记忆时把同类别的旧记忆一起交给模型，让它明确输出新增、更新、删除还是不动，减少重复条目和没被替换掉的旧事实。
- **先不做**：每轮多调一次模型来判断"这几条记忆和问题相关吗"。它会增加约 1 秒延迟和费用，先看 1、2 两项的效果，不够再加。
- **效果**：回答不再扯旧伤、旧化验；记忆跟得上变化（伤好了、换了器械）。§37、§39 里那些逐个补的规则可以收掉一部分。
- **证明**：新建 20 道记忆回归题，按研究里的五类组织：串入、迎合、知识更新、拒答、重复。串入率比基线降一半以上，原有记忆考题不变差，负责人"好"率不降。
- **依据**：Over-Personalization via Structured Memory（2026-08）、PersistBench（ICML 2026）、OP-Bench、BenchPreS、Zep、Mem0、LongMemEval。

### 第 3 步　路由与提速：简单问题只请一位专家（3–4 天）

- **现在**：每轮 7–15 秒；三路（模型、关键字、向量）意见常常不一致；超出范围的误判靠例句和词表事后兜底（§41）；辅助专家的意见往往都并进回答，回答变长。
- **改成**：
  1. 路由前先判断问题是单一领域还是跨领域。单一领域只请主责专家，不分层、不并行；真正跨领域时才组队。三个角色照常保留，不改回单 Agent。
  2. 只有三路不一致、或者前两名得分接近时，才让模型在"候选专家加超出范围"里裁决一次，并附上边界例句，例如"天气算训练"。
  3. 交给专家的任务说明写清四件事：目标、要填哪些输出字段、能用哪些工具、哪些不归它管。整合时，辅助专家有新信息才并入，没有就不加。
  4. 单独评测 Skill 选得准不准：每个角色该装的装上了没有。把描述相近的 Skill 合并，再补上"什么时候不用"。
- **效果**：延迟下降，答非所问减少，回答更短。
- **证明**：路由测评不变差；延迟中位数降 30% 以上（目标 ≤ 6 秒），P90 ≤ 12 秒；请了多位专家的轮次比例下降；负责人"好"率不降。§42 的"混合问题请全角色"考题必须全过，防止跨领域问题被判成单一领域而漏答。
- **依据**：Towards a Science of Scaling Agent Systems（Google 2025-12）、MDAgents、Anthropic 多 Agent 研究系统、OpenAI 建 Agent 指南、Self-MoA、不确定度驱动的超范围检测（ACL 2025）、Single-Agent with Skills（2026-01）。

### 第 4 步　Skill 进化管线：每一步都设关卡（4–5 天；必须在第 1 步之后）

- **现在**：Skill 全部由人写。运行框架的信号（核对改写、说不对、换说法重问、点了没用）只记录，不会反过来帮 Skill 变好。
- **改成**：每周一次离线处理：
  1. **找候选**：取有出错信号的轮次。
  2. **先归因**：路由不一致、数据缺失、判成超出范围这类问题不改 Skill 正文。只有确实是规程内容的问题才往下走。
  3. **出补丁**：每个角色只给**自己的** Skill 出"新增一条或修改一条"的小补丁，附上来源轮次和用户原话，不让模型整份重写。
  4. **自动验**：考题规则检查、红线子集、第 1 步校准过的评委，三项都过。
  5. **人审**：补丁进管理页的"待审"列表，负责人点通过才合入；合入后可以撤销。
  6. **跟效果**：每个 Skill 条目记"有用次数 / 有害次数"，按装载时和不装载时的信号率比较；长期没用的条目提示下线。
  - 红线 Skill（急症、伤病就医、禁忌）锁定，不出补丁。
  - 离线还可以在考题上同题多次采样、用规则检查比较优劣来提炼经验（Training-Free GRPO 的实验用的就是冻结的 DeepSeek）。
- **效果**：三个 Agent 各自越用越专业，每次变化都能追溯、能撤销、经过人的认可。
- **证明**：第一个月至少 5 条补丁被采纳；合入后对应信号的发生率下降，回归测试不变差。
- **依据**：ACE（2025-10）、ReasoningBank、Training-Free GRPO、GEPA（ICLR 2026 Oral）、SkillsBench、SkillLearnBench、SkillsVote、Misevolution。

### 第 5 步　安全与训练方案（2–3 天；第 1 步完成后可以和第 2、3 步并行）

- **现在**：急症靠规则判断，这一点研究支持。但没测过"症状被淡化"的说法，也没约束后面的模型改写会不会把就医级别降低。训练强度的写法比较自由，伤病禁忌靠提示词提醒。
- **改成**：
  1. 安全考题补两类：一类是淡化症状的说法（"家人说没事""可能只是累了""昨天就这样"）；另一类是"该先追问再判断"的情形。
  2. 规则判出的就医级别分四档：急诊、尽快就医、先追问、可以继续练。最终回答的级别不能低于规则给的，由代码检查。
  3. 训练计划里的强度只用 RPE、%1RM 或计算器给出的具体重量。档案里有伤病时，对照动作库已有的关节压力标注（`exercise_tags.yaml` 里的 stress）做硬拦截，不让禁忌动作进计划。
- **效果**：用户把症状说轻时，回答也不会把急症降级；带伤用户的计划里不会出现禁忌动作。
- **证明**：新增的安全题全部通过；计划检查里禁忌动作为 0；原有安全题不变差。
- **依据**：ChatGPT Health 分诊研究（Nature Medicine 2026-02）、CARE-Bench、Biology of Sport 2026 系统综述、运动处方一致性研究（2026-04）。

### 第 6 步　用真实效果衡量（持续）

- **现在**：只看考试分数。
- **改成**：管理页每周看一次：训练执行率、复盘方案的采纳率、"点了没用"的比例、换说法重问的比例、负责人每周抽 10 条的"好"率。
- **原因**：两项随机对照实验显示，模型本身并不能提高训练和饮食的执行率，执行率要靠计划和提醒。所以产品效果要看这些行为数据，不能只看考试分数。

## 三、明确不做

- 不再加"让模型自己反思再改"的轮次。同一个错误出现在模型自己的输出里时，它多半看不出来；研究里 DeepSeek 的自我纠错率只有 16.7%。现有的"规则核对、改写一次、规则修复"已经够了。
- 不让模型从零写新 Skill，也不靠模型自评做多轮迭代，这样会越改越偏。
- 不把点赞、换说法重问、评委分直接当质量分。
- 不默认用两两比较打分。两两比较只在新旧版本对比时用，并且交换顺序各评一次。
- 不把三个角色合成一个 Agent。研究里这是降延迟的一个选项，但负责人已经定了保留多 Agent，第 3 步改用"简单问题只请一位"来降延迟。

## 四、需要负责人定的

1. **第 0 步的 40 条补充标注**：约 40 分钟，用现有的评分页。这是整个方案的基础。
2. **由哪个会话执行本方案**：执行期间另一个会话只做单独指定的事。
3. **第 4 步的人审入口**：放在管理页，还是每周汇总成一份清单发给负责人。
4. **第 2 步"过期记忆请用户确认"的位置**：首页还是"我的"页。
